# B 파트 발표 요약 — 보안 / 크롬 확장

## 한 줄 소개

AI 챗봇에 민감정보가 **전송되기 직전에 막고**, 막은 기록은 **내용 없이 유형·시간만** 남기는 보안 계층을 맡았습니다.

## 시연 순서 (약 3분)

시연 5분 전에 `https://3bpmban7il.execute-api.ap-northeast-2.amazonaws.com/prod/api/health`를 한 번 열어 예열합니다(콜드 스타트 방지).

| 순서 | 할 일 | 보여줄 것 |
|---|---|---|
| 1 | `claude.ai` 입력창에 `900101-1234568` 입력 후 Enter | "전송이 차단되었습니다" 팝업, 유형 "주민등록번호" |
| 2 | 일반 문장(예: "안녕") 전송 | 차단 없이 그대로 전송 → 정상 입력은 막지 않음 |
| 3 | 팝업의 "안전하게 전송하기" 클릭 | SecureDrop 웹이 새 탭으로 열림 (A·C 파트로 연결) |
| 4 | 관리자 콘솔(`/admin.html`) 로그인 | 최근 이벤트에 `BLOCK / RRN / extension` 한 줄, 파일명·내용 없음 |
| 5 | 활성 전송에서 "강제 폐기" | 이벤트에 `REVOKE / admin` 기록, 링크 즉시 무효 |
| 6 (선택) | 업로드 화면에서 "브라우저에서 암호화해서 보내기" 체크 후 전송 → 휴대폰으로 스캔 | 휴대폰에서 원본 파일로 저장됨. S3에 있는 것은 암호문이라 열리지 않음 (PR #6 배포 후) |

## 설명 멘트 (핵심 5가지)

1. **막는 곳**: 확장이 전송 버튼·Enter를 가로채 서버의 탐지 규칙으로 검사합니다. 웹·확장·플러그인이 같은 규칙(`detector.py`) 하나를 씁니다.
2. **원문을 남기지 않음**: 서버에는 유형(RRN 등)과 시간만 기록합니다. 관리자 화면에도 파일명·내용·링크는 나오지 않습니다.
3. **서버가 응답하지 않으면 막음(fail-closed)**: 검사할 수 없으면 안전하게 전송을 막는 것이 기본값입니다. 설정으로 바꿀 수 있습니다.
4. **관리자만 로그인**: 일반 사용자는 로그인이 없고, 관리자 비밀번호는 scrypt 해시로만 저장하며 5회 실패 시 15분 잠깁니다.
5. **브라우저 암호화(선택)**: 파일을 보내기 직전에 브라우저에서 AES-256-GCM으로 암호화합니다. 키는 링크의 `#k=` 뒤에만 들어 있어 서버·CloudFront·S3 로그로 가지 않습니다. 서버와 S3에는 암호문만 있고, 받는 휴대폰 브라우저가 복호화합니다. 키가 틀리거나 파일이 바뀌면 복호화가 실패해 아무것도 저장되지 않습니다.

## 검증한 것 (숫자로 말하기)

- 탐지 테스트 **30건 전부 기대와 일치** (차단 15 / 정상 통과 11 / 알려진 한계 4), 배포 환경에서 실행
- 백엔드 자동 테스트 **56개 통과**
- 브라우저 암호화(PR #6): 단위 테스트 9개 통과(왕복·변조·틀린 키·IV 유일성), 키 포함 QR 9건 디코더 판독, mock 환경에서 업로드→복호화 확인. **실제 배포 환경 확인은 병합·배포 후**
- 보안 점검(배포 환경): S3 두 버킷 익명 접근 403, CloudFront 보안 헤더·HTTPS 강제, 관리자 API 무토큰 401, 플러그인 키 없이 403, 허용되지 않은 Origin에 CORS 헤더 없음
- 저장소와 git 이력에 실제 키·토큰 없음

## 한계 (질문이 나오기 전에 먼저 말하기)

| 한계 | 설명 | 향후 |
|---|---|---|
| 이미지·첨부파일 | 확장은 입력창에 **쓴 글자만** 검사합니다. 캡처 이미지나 AI 사이트에 직접 첨부한 파일은 검사하지 않습니다. | 이미지 글자 인식(OCR), 첨부 파일 가로채기 |
| 정규식의 한계 | 한글로 쓴 숫자("공일공…"), 이름·주소, 체크섬이 틀린 임의 주민번호는 못 잡습니다. | 문맥 기반 탐지 |
| 유형 중복 집계 | 유효한 주민번호가 카드번호로도 함께 집계될 수 있습니다(차단 자체는 정확). | 중복 제거 규칙 |
| 사이트 UI 변경 | AI 사이트 화면이 바뀌면 가로채기가 실패할 수 있습니다. 선택자는 `content.js` 한 곳에 모아 두었습니다. | 다중 사이트 지원 |
| 검사 단계 평문 | 검사할 때는 서버가 평문을 봅니다(저장은 안 함). 암호화는 **저장·전송 구간**을 보호합니다. | 브라우저 로컬 검사 |
| 암호화의 범위 | QR을 가진 사람은 키도 가집니다. 링크를 복사하면 키까지 복사됩니다. 암호화하면 파일이 28바이트 커져 20MB 상한에 걸릴 수 있습니다. | 키 별도 전달, 비밀번호 방식 |

## 예상 질문과 답

- **"이미지로 올리면요?"** 지금은 막지 못합니다. PRD에 비목표로 정했고, OCR을 향후 과제로 둡니다.
- **"서버가 죽으면요?"** 기본은 전송을 막습니다(fail-closed). 사용자가 설정으로 끌 수 있지만 기본은 안전 쪽입니다.
- **"관리자는 사용자 파일을 볼 수 있나요?"** 아니요. 관리자 화면에는 유형·시간·크기·상태만 보이고 파일명·내용·다운로드 링크는 없습니다.
- **"탐지가 틀리면요?"** 차단·허용은 규칙 기반 검사 결과로만 결정하고, 오탐·미탐 케이스는 `tests/test_cases.md`에 정리해 한계로 공개합니다.

## 아직 확인이 필요한 것 (발표 전 A에게)

- CloudWatch 로그·DynamoDB에 원문·파일명·Presigned URL이 없음 (AWS 콘솔 확인)
- `sd_admins`는 해시만, 세션·관리 토큰은 SHA-256만 저장됨
- 두 S3 버킷의 Block Public Access 4개 설정
